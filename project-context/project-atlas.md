## 1. 一句话：这个项目究竟要做什么

这是一个 **AI 产品经理的求职作品集**，不是面向真实用户的生产产品。它要证明的不是"我会做页面"或"我调好了一个模型"，而是一条**面试官能亲手走一遍、又能被证据追到底的完整闭环**：

> 聊天时 AI 记住正确的事 → 能解释为什么这么记、这么用 → 用评测发现问题 → 修产品策略 → 用 Before / After 和 Bad Case 证明真的变好了。

当前最重要的产品问题是一个代号叫 **E004** 的缺陷：**聊"今天天气不错"这种无关话题时，系统还可能把"失眠""橘猫"这些旧记忆翻出来，污染 AI 的回复**。它到现在还没有解决，是整条闭环里最扎眼、也最有讲头的一环。

## 2. 目标用户：为什么聚焦"中期和重度用户"

这个项目解决的，是 AI 陪伴类社交产品（比如 Alice 这类）里的一个具体问题。

用户流失按生命周期分层，而 **Memory 只在其中几层是主责**：

| 流失阶段 | 大约占比 | Memory 是不是主责 | 本项目 |
|---|---|---|---|
| 首日流失 | 约一半 | 不是（是首屏、角色、首聊问题） | 不覆盖 |
| 短期流失（第 3、7 天） | 约两成 | 部分是 | 覆盖 |
| 中期流失（3–7 天） | 约一成多 | 是 | **核心** |
| 重度流失（突然断崖） | 约不到一成 | 是，优先级最高 | **核心** |

**为什么聚焦中期和重度**：首日流失的根子在"第一印象"，不在记忆；而一个用户用了三五天、七八天之后突然不来了，往往是因为 AI"忘了我说过的话""把我记错了""翻来覆去说一样的话"——关系断了，人就走了。这些人恰恰是留下来最久、价值最高的用户，所以把 Memory 做好，直接打的是"关系连续感"这个命门。

## 3. 核心问题：AI 的"失忆、误记、乱用"怎么破坏关系

一段关系能不能延续，靠的是"你记得我、你懂我"。AI 在这件事上会犯三种错：

1. **失忆**：说过的事转头就忘，用户觉得"跟它聊了个寂寞"；
2. **误记**：记错了、记串了，用户觉得"这 AI 不靠谱"；
3. **乱用**：在完全无关的场合把旧记忆硬塞进回复，比如聊天气时突然扯到"你家的猫半夜跑酷"——用户会觉得"它根本没在听我说话"。

这三种错，最终都指向同一个结果：**用户不再相信"AI 真的记得我"，关系连续感断裂，然后流失**。

E004 就是"乱用"最典型的例子，所以它被当作整条闭环的试金石。

## 4. 完整产品闭环（这张地图想证明的能力）

```text
真实聊天
  → Memory 写入（什么值得记）
  → Memory 召回（当前该用哪些）
  → Memory 更新 / 删除（记错了要改，删了不能再冒出来）
  → Trace（解释每一步发生了什么、为什么）
  → Eval（用评测发现问题）
  → Bad Case（把问题沉淀成案例）
  → 产品决策与修复（改策略）
  → Before / After（证明真的变好了）
```

这八步构成一条可以被面试官验证、被证据追到底的纵向闭环，不是一句口号。项目里每一条都已经有对应的真实实现或明确缺口（见第 7 节）。

## 5. 产品蓝图：三层 Demo 目标形态，外加一层"叙事"

> **这一节描述的是"最终要长成什么样"的产品蓝图，不是"现在已经全部有了"。** 每一项能力的当前真实状态，见第 7 节四态表；蓝图里标「已可用」的，才能被面试官当场点开验证。

### 三层 Demo（目标产品形态）

1. **用户侧产品**：消息列表、AI 私聊页、AI 角色主页、Memory 管理、主动消息与隐私安全设置。**当前状态**：核心私聊链路已可用（聊天、Memory、Trace）；AI 角色主页、主动消息、隐私安全设置属产品形态/后续方向，尚未全部实现。
2. **产品策略后台**：用户画像、关系阶段、Memory、Prompt 版本、Persona、主动触发规则、安全规则。**当前状态**：部分已有（快照能解释配置、真实评测可见），完整后台属后续方向。
3. **质量层（Eval / Trace / Bad Case）**：真实评测结果、每一步的 Trace 证据、Bad Case 复盘。**当前状态**：8 Case 真实 Eval 与 Trace 已实现；完整 Bad Case 生命周期尚未实现。

### 一层"作品集叙事层"（不是第四层功能）

这是给面试官**讲清楚**上面三层的能力：把问题、决策、证据、失败和下一步串成一条 10–15 分钟能讲完、又能随时下钻到证据的故事线。

**它是一套讲述方法，不是产品功能。** 不会为它单独建一个后台页面，也绝不把它和三层 Demo 混为一谈。

## 8. R1—R4 决策时间线：我们一路试了什么、为什么停

这条时间线的价值，在于**它证明了"不是拍脑袋改一版就行，而是每走一步都停下来看证据、诚实认失败、再换路"**——展示的是判断过程，不是"已经做成了什么效果"。

| 轮次 | 试了什么 | 结果 | 为什么停 / 转向 |
|---|---|---|---|
| R1 | 本地相关性 Gate（第一轮 Spike） | 停止 / 失败 | 两个候选方案都达不到独立盲测、延迟和资源要求 |
| R2 | 公开方案调研 + 本地 Cross-Encoder 方向 | 候选 A 停止、候选 B 暂停 | 候选 A（cross-encoder）因权重缓存缺失停止；候选 B（k-means）由 Founder 指示暂停（注意：停止 ≠ 暂停，两者原因不同） |
| R3 | 三方案对照：零依赖阈值基线 / 本地重排 / 外部大模型裁判 | 三方案全部停止 / 失败 | 分离边际分别为 −0.23 / −0.38 / −0.57，都触发停止线；方案 C 还波动 0.35，判据失效 |
| R4 | 转向"上下文记忆可用性判断"：让判断器同时看到当前问题、最近对话、候选记忆，输出"用/不用/证据不足" | **部分有效、整体未通过** | 合成场景中"乱用无关记忆"从 13/13 降到 0/13（内部实验记录，非作品集效果结论）；但"关键记忆不能漏"连续两轮失败（过敏记忆被当普通偏好），"证据不足"独立成档也没做到，且对照组 A 仅 1/3 正确。不启动第五轮 |

**为什么最后停在 R4 而不是硬凑一个"通过"**：因为"该用的时候不漏"这条最重要的护栏没守住，且整体正确率只有 56.7% / 60%，合成数据也不代表真实表现。诚实停在失败，比假装修好更能说明一个 PM 的判断力。

**哪些证据支持、哪些证据否决**：R4 的正向信号只出现在合成实验里（"显式判断能减少无关记忆硬扯"），它是**内部实验记录，不是已证实的产品效果结论，也不能证明 E004 已解决**；否决的是"关键记忆漏用两轮未解决"和"三档判断不可靠"。目前**没有任何一条证据支持"E004 已被解决"**。

## 10. 面试时可以展开讲的产品判断

1. **为什么先做"能解释每次评测用了什么配置"（TASK-005A），再去做"优化评测结果"（TASK-006）**——如果连"为什么结果变了"都说不清，改绿了也不能证明是你改对的。
2. **为什么对"用外部大模型做相关性判断"这件事反复犹豫**——效果好不等于能上产品：隐私边界、墙钟延迟、失败回退、证据治理，四件事一起过门才算数。
3. **为什么 TASK-004（删除后不再复活）暂停了**——物理删除有效，但未来对话仍可能重新抽取；轻量方案做不到"零误删 + 高召回"同时成立，所以不降低标准硬宣称通过。
4. **为什么 R4 最后主动停手**——"该用不漏"是比"不乱用"更硬的底线，底线没守住就不发布。要讲的是"为什么尝试、为什么否决、为什么停手"的判断过程；其中"减少乱用"只是合成实验的内部信号，**不能当作已证实的作品集产品效果**。
