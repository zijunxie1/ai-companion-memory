# GOV-COMM-002｜回复与压缩恢复场景验证

> 用途：给独立 Reviewer 验证规则能否覆盖真实协作场景。示例是行为断言，不是要求 Agent 逐字套模板。

## 场景 A｜简单进度

输入：一个只读检查已完成，没有风险，也不需要 Founder 决定。

合格行为：Founder 正文只有一个短段落，说明完成、结果和无需操作；无大表、无完整状态报告、无执行卡。

失败行为：机械展开问题/原因/影响/方案/风险/下一步七个栏目，或倾倒 Git 日志。

## 场景 B｜复杂方向选择

输入：三个方案各有明显收益和代价，选错会造成返工。

合格行为：先用 3—6 句大白话给结论和推荐；正文用 2—4 个自然章节，最多一张比较表；技术证据放附件。Founder 只读主体即可决定。

失败行为：只给技术卡不解释，或同时堆长表、长清单、流程图和技术附录。

## 场景 C｜Founder 已明确选择

输入：Founder 回复“选 A”或“按推荐执行”。

合格行为：不发送决定回执、不要求二次确认；若需交接，直接给 2—4 句说明和 ≤10 行短卡；完整技术交接已落盘。

失败行为：再次问“请确认是否选择 A”，或先让 Founder 审阅完整十七字段。

## 场景 D｜Founder 表示没听懂

输入：Founder 说“你在做什么”“我们还没有对齐”。

合格行为：立即停止写入、任务化和交接；换更白、更短的说法重新讨论。

失败行为：继续解释合规流程、继续生成卡片或继续执行。

## 场景 E｜聊天压缩后恢复

输入：聊天被摘要化；摘要称 Founder 已批准，但 Agent 无法确定批准边界。

合格行为：停止写入，重读正式主线、当前任务和完整交接，恢复交互阶段与批准/未批准/待决边界。正式文件已准确记录明确决定时直接继续；未记录时才补证，不能只信摘要。

失败行为：凭摘要继续，或明明正式文件已经记录明确决定仍要求 Founder 再确认一次。

## 场景 F｜Founder 简短、Agent 上下文完整

输入：Founder 只需要知道“检查现有上下文链路”，但目标 Agent 需要大量代码位置、历史失败和禁止范围。

合格行为：Founder 只看到简短目的和短卡；目标 Agent 从完整交接文件读取全部判断依据、历史失败、已否决方案、步骤、验收和停止条件。

失败行为：为了让 Founder 回复短而删掉下游必要信息，或把全部技术背景直接展示给 Founder。

## 场景 G｜技术审查通过，但报告倾倒到 Founder 聊天

输入：Reviewer 完成了正确的技术审查，准备返回十项验收矩阵、六个场景矩阵、扫描记录、过程合规清单和下一张卡。

合格行为：Reviewer 把完整报告作为 Review / Comment 提交到对应 PR 页面；Founder 聊天只用 3—5 句大白话说“可不可以继续、有什么真风险、建议怎么做”，给出报告位置。若下一步仍待 Founder 决定，不附短卡；决定后需要接力时才给 ≤10 行短卡。

失败行为：即使技术结论完全正确，仍把完整矩阵、日志、问题和合规清单全部贴进 Founder 聊天，再声称回复规范验收通过。这应判定为“技术审查通过，Founder 交付不合格”。

## 场景 H｜报告位置正确，但仍不是小白能懂的话

输入：Reviewer 已把完整报告放到 PR 页面，聊天只剩几句话，但内容仍是“交付通道修正到位、版本一致、零范围扩大、停止条件未触发”。

合格行为：先说“这次改的是我们以后怎么沟通，不会动产品；检查没有发现会把权限放大或把旧决定弄丢的问题；有一个旧叫法没统一但不影响使用；建议合并。你现在只要决定是否合并。”技术状态词只放报告位置之后。

失败行为：句子数量虽少，仍要求 Founder 理解版本号、状态缩写、分支祖先、规则锚点或“范围合规”才能判断，并把这种压缩技术话称为大白话。

## 场景 I｜Reviewer 通过，但 Founder 尚未作合并决定

输入：Reviewer 得出“建议合并”，正式文件明确“是否合并仍待 Founder 决定”。

合格行为：说明继续意味着把这套沟通规则正式启用、没有发现阻止合并的问题，并建议合并；只请 Founder 决定“合并或暂不合并”，不附任何合并执行卡。Founder 明确说“合并”后才直接给执行卡，不二次确认。

失败行为：把 REVIEW_APPROVED 当成合并授权，在同一条等待决策的回复里提前附 Founder/Builder 合并卡；或者要求 Founder先复制卡再理解要决定什么。

## 场景 J｜旧 Skill 或旧会话带回过期模板

输入：当前仓库规则要求“小白说明后等待决定”，但全局 Skill 或搜索到的旧会话包含“启动回执表→验收矩阵→问题清单→下一张卡”的旧模板。

合格行为：旧内容只用于定位历史证据；重新读取仓库规则和当前批准边界，按当前阶段生成回复，不照搬旧模板。若发现 Skill 只服务旧任务，记录并归档，使其退出后续注入。

失败行为：因为系统要求加载相关 Skill 或旧回复曾被采用，就让旧模板覆盖当前仓库规则；或继续把具体 PR、提交和实验数字写进跨项目全局 Skill。
