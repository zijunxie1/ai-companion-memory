## 3. 候选机制（最多两个；针对 R1/R2 提出，不预先选定；本 DRAFT 只定候选方向与验证框架）

> 遵循路线 B（不向外部模型/数据服务发送任何用户数据）+ Founder 裁决 A（不补词、不重跑冻结 holdout、不重启外部模型路线）。
> **"不预先选定方案"**：两个候选均执行并如实报告；至少一个通过 §8 全部门即形成"存在可行候选"结论；单个失败只记录不停止；两个都失败才停止（停止条件 9）。
> **两候选独立性（Founder Review 1 第 5 条）**：候选 A 与候选 B 互相独立，各自核对各自适用门；任一候选降级/失败不影响另一候选独立评估与通过。

### 3.0 mem0 现状基线（用于对照数学差异）

mem0 当前召回分数 = 查询 embedding 与记忆 embedding 的**单一余弦相似度**（同模型 `BAAI/bge-small-zh-v1.5`，本地 fastembed 推理）。它不含：多维交互结构、检索集合内相对分布、主题空间信息。

### 3.1 候选机制 A：本地语义交互 + 集合相对特征 Gate（针对 R1 词法不可分）

**输入**：查询文本 `q` + 候选记忆文本 `m` + 本次 mem0 检索的候选集合 `S`（q 与 m 经本地 fastembed 得向量 `v_q`、`v_m`）。

**计算步骤**：
1. 逐对交互特征（非单一余弦）：`dot = v_q·v_m`（余弦分子）、`prod = v_q ⊙ v_m`（逐元素乘积向量）、`absdiff = |v_q − v_m|`（逐元素绝对差）、`signmatch = 1[sign(v_q) == sign(v_m)]` 逐元素一致率——这些是多维交互结构，mem0 单一余弦不含；
2. 集合相对特征：对 `S` 内所有候选的 mem0 原始分计算均值/标准差 → `z = (score_m − mean_S)/std_S`；并取 `rank` = 候选在 S 中按相似度排序的相对位次归一化——mem0 分数本身不含集合分布信息；
3. 将上述特征拼接为特征向量，经线性组合 + sigmoid 映射到 (0,1)（权重/阈值在校准集上调，随机制冻结）。

**输出分数**：0–1 连续相关性分数。

**针对第一轮根因的新增能力（R1）**：对"记忆文本几乎相同但查询语义不同"的正负对（E001"失眠" vs E004"天气" 对同一橘猫记忆），候选 A 通过**多维交互结构**（语义方向差异不只在余弦一维）与**集合相对分布**（该记忆在本次检索结果中的相对位置）提供 mem0 单一余弦之外的新信号。

**冗余降级规则（Founder Review 1 第 1 条）**：若实现中实际只使用单一余弦（如仅 `dot` 一项），或经非冗余诊断 ρ ≥ 0.9，则**自动降级为冗余基线**，不作为正式候选；不得以"多维特征名义上存在但实际无增益"规避。降级不影响候选 B 独立评估（§8 验收 2）。

### 3.2 候选机制 B：本地 embedding 校准集原型聚类 Gate（针对 R2 手工词表覆盖不足）

**输入来源（全部列出，Founder Review 1 第 3 条）**：
- (a) 正式 8 Case 种子文本（`v2/migrations/002_eval.sql` E001–E008，已批准）；
- (b) 第一轮已入库校准检索样本文本（`spike/data/calibration/round-{1,2,3}/`，合成数据，已批准入库）；
- 以上为**唯一输入**；**不使用任何"通用知识"、未批准语料、人工词表、下载模型或新增依赖**（k-means 用纯 JS 实现或现有依赖实现，零新增包）。

**计算步骤（单一方法：k-means 原型聚类）**：
1. 用本地 fastembed 将输入文本集合嵌入为向量集；
2. 对该向量集执行 **k-means 聚类**（k 为人工设定的元参数，仅在校准集上选定并随机制冻结；聚类本身纯数据驱动）得到 `k` 个主题原型向量 `P = {p_1…p_k}`；
3. 查询 `q` 与记忆 `m` 分别映射为与各原型的相似度分布 `a_q = [cos(v_q,p_1)…cos(v_q,p_k)]`、`a_m = [cos(v_m,p_1)…cos(v_m,p_k)]`；
4. 相关性 = 两分布加权相似（如加权余弦/JS 散度补数），映射到 (0,1)。

**输出分数**：0–1 连续相关性分数。

**针对第一轮根因的新增能力（R2）**：主题空间由**数据自动构建**（聚类），不依赖手工枚举词表；未见于词表的表达（如"下雨"）通过 embedding 自然落入原型分布，不因"词表未命中"而信号归零。

**人工输入边界**：人工仅设定元参数 `k`（聚类数）与相似度阈值；**不得人工枚举主题词表、不得人工标注原型语义**；空间构建只使用上述输入 (a)(b)，不使用 holdout 内容。

> 两个候选的详细机制（特征权重、k 选择、评估顺序）由 Builder 在实施计划中给出，**但不得超出上述两个候选方向与输入来源**；若证明需要第三机制、外部模型、未预装组件或新语料，停止并提交范围/依赖裁决。

## 5. 校准、非冗余诊断与冻结 Holdout（沿用第一轮纪律，DRAFT v1.2 §5 全量继承）

### 5.1 数据边界（不变）

- 只允许**合成评测数据** + 评测专用 user_id（`eval-spike-r2-<candidate>-<rand>` 格式）；**不得读取、复制或落盘真实用户内容**；
- 仅允许 loopback 本地服务；禁止一切非本机网络；
- 禁止运行时下载模型、权重或依赖；开始前按 §5.4 预装检查（P1–P6 沿用第一轮清单，含 fastembed 缓存核验）。

### 5.2 非冗余诊断（候选 A 专用；候选 B 信号源不同不依赖此诊断）

- 校准集计算候选 A 分数与 mem0 原始 score 的 Spearman ρ；ρ ≥ 0.9 → 降级冗余对照，**仅候选 A 降级，不影响候选 B 独立评估**；ρ < 0.9 仅证明非冗余，仍须通过全部质量/延迟/资源/泛化门；
- **冗余降级自检（Founder Review 1 第 1 条）**：除 ρ 外，候选 A 报告必须自查实现是否实际只使用了单一余弦（如仅 `dot` 一项）——若是，同样视为冗余基线，不作为正式候选。

### 5.3 校准集与冻结 Holdout（四步顺序不可颠倒）

1. **校准集**：E001–E005 场景真实本地检索样本，三轮重复采集（mem0 检索非确定性，禁止单轮结论）；
2. **标签规则**：正/负样本定义与人工复核沿用第一轮（关键词初判 + 人工复核，复核记录入库）；
3. **冻结 holdout（3–5 个场景，不参与调参）**：覆盖困难负例类型——多义词、他人属性、语义隐式关联、**未见过表达泛化（含第一轮失败类型"新天气表达"的新文本，禁止复用 H4 原文）**；S1 冻结（场景/标签/哈希），内容不得用于设计/调整任何候选机制；
4. **执行顺序**：① holdout 数据冻结 → ② 校准调参（仅校准集）→ ③ 机制冻结（版本 + 哈希）→ ④ holdout 一次性运行（运行后禁止继续调参）；
5. **可靠性判据（不变）**：校准集与冻结 holdout 各自 **F1 ≥ 0.9 且分离边际 > 0.1**；实测波动 > 0.1 → 判据自动失效 → 停止条件 1；
6. **样本量诚实声明**：如实声明样本量与置信局限；
7. **Reviewer 核对**：Builder 只提供冻结记录与提交历史，核对结论由独立 Reviewer 写入审查报告；
8. **holdout 隔离纪律（Founder Review 1 第 6 条）**：
   - **候选设计不得读取 holdout 具体文本、标签或词汇**：候选机制设计（S2 之前）只接触校准集与已批准契约；holdout 场景类型（多义词/他人属性/隐式关联/新表达）为已批准 DRAFT 预声明信息，但**具体文本、标签、词汇只在 S1 冻结后写入 `holdout-definition.json`，候选设计阶段不得打开该文件**；
   - **隔离方式**：① Git 隔离——S1 holdout 冻结提交必须**先于**任何候选机制设计提交（Reviewer 核对提交历史顺序）；② 数据路径分离——候选评分脚本只接收校准集数据路径参数，holdout 数据仅在 S7 一次性运行脚本中读取；③ 词表审计——候选 B 若产生任何聚类原型/词项输出，Spike 报告须对照 holdout 冻结内容证明无重叠（无 holdout 特有词进入机制）；
   - **可审计证据**：holdout 冻结时间戳/提交号/内容哈希（S1）+ 候选机制冻结时间戳/提交号/哈希（S3）+ 两者提交历史先后核验记录，全部入库供 Reviewer 核对。

### 5.4 预装检查（沿用第一轮，Spike 开始前强制门）

## 6. 延迟与资源门（沿用第一轮口径，DRAFT v1.2 §6 全量继承）

## 8. 验收标准（Spike 通过门；至少一个正式候选通过全部适用门 + 统一门即形成"存在可行候选"结论）

> **候选独立性（Founder Review 1 第 5 条）**：候选 A 与候选 B 各自核对**自己的适用门**（第 2 项），任一候选被降级/失败**不得阻止另一候选独立通过**；通过适用门后，两者统一接受第 3–11 项质量/延迟/资源/数据边界门。**"至少一个候选通过"的判断在候选级独立完成**——若候选 A 降级为冗余基线，候选 B 仍可单独通过并形成"存在可行候选"结论。

1. 预装检查通过（P1–P6，含 fastembed 缓存）；
2. **各候选适用门（互相独立）**：
   - 候选 A：通过非冗余诊断（ρ<0.9）**且**冗余降级自检通过（实现非单一余弦）；任一失败 → **仅候选 A 降级为冗余基线**，不参与后续门，**不影响候选 B**；
   - 候选 B：通过数据驱动定义核对（单一方法 k-means、输入来源仅 (a)(b)、无人工词表、无未批准语料/模型/依赖）；
3. 每个正式候选输出 0–1 连续可校准分数，完成 ≥3 轮真实本地检索测量；
4. 校准集 F1 ≥ 0.9 且分离边际 > 0.1（每候选分别评估）；
5. 冻结 holdout 一次性运行 F1 ≥ 0.9 且分离边际 > 0.1（四步顺序执行；运行后无继续调参）；
6. 延迟门：增量 P95 ≤ 200ms、总预算 P95 ≤ 1000ms；

8. 网络与数据边界：仅 loopback、零非本机调用、仅合成数据、种子清理核验；
