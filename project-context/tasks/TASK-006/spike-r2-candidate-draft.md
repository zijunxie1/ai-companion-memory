## 1. 任务目标（一句话）

在**不接入产品路径、不外发任何用户数据、仅使用已预装本地组件**的前提下，用独立、限时的第二轮 Spike 验证**针对第一轮失败根因设计的新候选机制**（最多两个）能否可靠分离 E004 无关召回与 E001 等正向召回，为 TASK-006 后续 Change Request 提供可复现的技术可行性证据。

> 第二轮 Spike 通过只代表"技术可行"，**不代表 TASK-006 完成**；产品实现必须另经 Founder 批准的新 Change Request 与实施计划。

## 3. 候选机制（最多两个；针对 R1/R2 提出，不预先选定；本 DRAFT 只定候选方向与验证框架）

> 遵循路线 B（不向外部模型/数据服务发送任何用户数据）+ Founder 裁决 A（不补词、不重跑冻结 holdout、不重启外部模型路线）。
> **"不预先选定方案"**：两个候选均执行并如实报告；至少一个通过 §8 全部门即形成"存在可行候选"结论；单个失败只记录不停止；两个都失败才停止（停止条件 9）。

### 候选机制 A：本地语义层二次相关性 Gate（针对 R1 词法不可分）

- **方向**：用**已预装本地 embedding 能力**（fastembed 缓存，仅本地推理）构建查询 ↔ 候选记忆的**语义相关度信号**，与第一轮候选 1 的纯词法信号、与 mem0 原始 score 均不同源/不同用法；
- **必须满足（防重蹈 R1）**：信号必须能区分"记忆文本几乎相同但查询语义不同"的正负对（E001"失眠"vs E004"天气"对同一橘猫记忆）——这是第一轮词法失败的核心场景，第二轮候选 A 必须在此场景证明分离能力；
- **非冗余诊断（沿用第一轮纪律）**：校准集计算候选 A 分数与 mem0 原始 score 的 Spearman ρ；ρ ≥ 0.9 → 降级为冗余对照，不作为正式候选；ρ < 0.9 仅证明非冗余，仍须通过全部质量/延迟/资源/泛化门；
- **信号实现约束**：仅使用已预装本地组件（fastembed 模型缓存），不得调用外部模型、不得下载新模型；实现细节（特征组合/交互方式）由 Builder 在实施计划中给出，**不得针对"天气/猫/失眠/小橘"字面量设计**。

### 候选机制 B：数据驱动主题/语义空间 Gate（针对 R2 手工词表覆盖不足）

- **方向**：不依赖手工枚举主题词表，改用**数据驱动方式**从校准集文本构建主题/语义空间（如基于本地 embedding 的原型聚类、或本地统计主题模型），查询与记忆映射到该空间后计算相关性；
- **必须满足（防重蹈 R2）**：对**未见于校准集的表达**（如"下雨"类天气变体、多义词新语境）必须仍能产生有效相关性信号（不得因"词表未命中"而信号归零）；
- **覆盖泛化验证**：冻结 holdout 中必须包含第一轮失败场景 H4 的同类变体（新天气表达）作为泛化检查，但**不得复用第一轮 H4 的具体文本**（避免"针对已知失败点设计"的偏差）；
- **人工输入边界**：可人工定义"主题空间构建的元参数"（如聚类数、相似度阈值），但**不得人工枚举主题词表**；空间构建只使用校准集 + 通用知识，不使用 holdout 内容。

> 两个候选的详细机制设计（特征、算法、参数、评估顺序）由 Builder 在实施计划中给出，**但不得超出上述两个候选方向**；若证明需要第三机制、外部模型或未预装组件，停止并提交范围/依赖裁决。

## 5. 校准、非冗余诊断与冻结 Holdout（沿用第一轮纪律，DRAFT v1.2 §5 全量继承）

### 5.1 数据边界（不变）

- 只允许**合成评测数据** + 评测专用 user_id（`eval-spike-r2-<candidate>-<rand>` 格式）；**不得读取、复制或落盘真实用户内容**；
- 仅允许 loopback 本地服务；禁止一切非本机网络；
- 禁止运行时下载模型、权重或依赖；开始前按 §5.4 预装检查（P1–P6 沿用第一轮清单，含 fastembed 缓存核验）。

### 5.2 非冗余诊断（候选 A 专用；候选 B 信号源不同不依赖此诊断）

- 校准集计算候选 A 分数与 mem0 原始 score 的 Spearman ρ；ρ ≥ 0.9 → 降级冗余对照，不作为正式候选；ρ < 0.9 仅证明非冗余，仍须通过全部质量/延迟/资源/泛化门。

### 5.3 校准集与冻结 Holdout（四步顺序不可颠倒）

1. **校准集**：E001–E005 场景真实本地检索样本，三轮重复采集（mem0 检索非确定性，禁止单轮结论）；
2. **标签规则**：正/负样本定义与人工复核沿用第一轮（关键词初判 + 人工复核，复核记录入库）；
3. **冻结 holdout（3–5 个场景，不参与调参）**：覆盖困难负例类型——多义词、他人属性、语义隐式关联、**未见过表达泛化（含第一轮失败类型"新天气表达"的新文本，禁止复用 H4 原文）**；S1 冻结（场景/标签/哈希），内容不得用于设计/调整任何候选机制；
4. **执行顺序**：① holdout 数据冻结 → ② 校准调参（仅校准集）→ ③ 机制冻结（版本 + 哈希）→ ④ holdout 一次性运行（运行后禁止继续调参）；
5. **可靠性判据（不变）**：校准集与冻结 holdout 各自 **F1 ≥ 0.9 且分离边际 > 0.1**；实测波动 > 0.1 → 判据自动失效 → 停止条件 1；
6. **样本量诚实声明**：如实声明样本量与置信局限；
7. **Reviewer 核对**：Builder 只提供冻结记录与提交历史，核对结论由独立 Reviewer 写入审查报告。

### 5.4 预装检查（沿用第一轮，Spike 开始前强制门）

P1 mem0-server loopback 可达 → P2 版本 → P3 PostgreSQL/评测表 → P4 Node/pg 依赖 → P5 fastembed 模型缓存存在（**禁止执行会触发下载的实例化命令**）→ P6 网络边界环境审计。任一缺失 → 立即停止，提交范围/依赖裁决，不得安装。

## 6. 延迟与资源门（沿用第一轮口径，DRAFT v1.2 §6 全量继承）

- **测量口径**：预热 5 次；每场景有效样本 ≥ 30；P95 = `ceil(0.95×N)` 位；进程边界 = 只测候选机制函数本身；**基线 = 仅本地检索；处理组 = 同一次检索 + 候选 Gate；增量 = 处理组 − 基线**；候选函数单独耗时仅参考，不得用作增量；
- **通过门**：增量 P95 ≤ 200ms；总预算 P95 ≤ 1000ms；内存峰值 ≤ 512MB；CPU 单次 ≤ 500ms；失败回退如实记录（keep-all 回退会恢复 E004 缺陷，不得表述为修复）；
- 延迟/资源门是 Spike 通过门，不是产品最终承诺。

## 8. 验收标准（Spike 通过门；至少一个正式候选通过全部 1–11 项即形成"存在可行候选"结论）

1. 预装检查通过（P1–P6，含 fastembed 缓存）；
2. 候选 A 通过非冗余诊断（ρ<0.9）且候选 B 通过数据驱动定义核对（无手工词表、对未见表达有效）；ρ<0.9 仅证明非冗余，仍须通过其余全部门；
3. 每个正式候选输出 0–1 连续可校准分数，完成 ≥3 轮真实本地检索测量；
4. 校准集 F1 ≥ 0.9 且分离边际 > 0.1（每候选分别评估）；
5. 冻结 holdout 一次性运行 F1 ≥ 0.9 且分离边际 > 0.1（四步顺序执行；运行后无继续调参）；
6. 延迟门：增量 P95 ≤ 200ms、总预算 P95 ≤ 1000ms；
7. 资源门：内存 ≤ 512MB、CPU ≤ 500ms；
8. 网络与数据边界：仅 loopback、零非本机调用、仅合成数据、种子清理核验；
9. 零产品改动：分支 diff 仅含 TASK-006 文档与 `spike-r2/` 文件；
10. 证据完整落盘：脚本、原始数据、标签复核、冻结记录（时间戳/提交号/哈希）、审计、失败尝试；
11. 报告诚实：样本量声明、波动范围、失败记录（含失败候选）、ρ、增量口径、与 DRAFT v1.2 判据对标、**"Spike 通过 ≠ TASK-006 完成"声明**。

**回归证明**：E001/E003 正向场景在冻结机制下逐轮指标（候选不砍正向召回）；强约束（E006/E007/E008）不涉及（零产品改动）。

## 9. 停止条件（满足任一 → 停止，提交 Change Request / 返回 Founder，不得继续调参）

1. 所有正式候选都无法安全分离（各自校准或 holdout 分离边际均 ≤ 0.1，或波动 > 0.1 判据失效）；
2. 修 E004 必然导致 E001 等正向召回明显退化；
3. 必须削弱测试、修改判定规则、**手工枚举词表**或针对固定字面量硬编码才能变绿；
4. 需要超出批准范围的改动（含必须外发才能解决）；
5. 无法建立与校准数据独立的冻结 holdout 证据；
6. 本地组件未预装或需运行时下载/安装；
7. 发现用户数据外发路径或非本机网络访问；
8. 限时到期（5 工作日 / 3 轮）未收敛；
9. 两个正式候选都失败（单候选失败只记录，不停止）。
