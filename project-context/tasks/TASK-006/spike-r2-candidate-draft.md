## 3. 候选机制（最多两个；针对 R1/R2 提出，不预先选定；本 DRAFT 只定候选方向与验证框架）

> 遵循路线 B（不向外部模型/数据服务发送任何用户数据）+ Founder 裁决 A（不补词、不重跑冻结 holdout、不重启外部模型路线）。
> **"不预先选定方案"**：两个候选均执行并如实报告；至少一个通过 §8 全部门即形成"存在可行候选"结论；单个失败只记录不停止；两个都失败才停止（停止条件 9）。
> **两候选独立性（Founder Review 1 第 5 条）**：候选 A 与候选 B 互相独立，各自核对各自适用门；任一候选降级/失败不影响另一候选独立评估与通过。

### 3.0 mem0 现状基线（用于对照数学差异）

mem0 当前召回分数 = 查询 embedding 与记忆 embedding 的**单一余弦相似度**（同模型 `BAAI/bge-small-zh-v1.5`，本地 fastembed 推理）。它不含：多维交互结构、检索集合内相对分布、主题空间信息。

### 3.1 候选机制 A：本地 cross-encoder 相关性重排 Gate（方向已批准；具体模型未批准——约束 1/2/4）

> **方向依据（调研方案 1/4）**：cross-encoder 重排是业界成熟的相关性重排范式（bge-reranker 系为代表性开源实现，FlagEmbedding 仓库 MIT；fastembed（Qdrant）文档提供 `TextCrossEncoder.rerank(query, documents)` 接口，项目 mem0-server 已使用 fastembed）。
> **⚠️ 批准边界（Founder 约束 1/2/4）**：本 DRAFT 只批准"本地 cross-encoder 重排"这一**方向**；**不批准任何具体模型或权重**。fastembed 接口在本机是否可用、具体权重是否已缓存，均为**待核验事实**（§5.4 P5），**不得表述为既成事实**。在具体模型名称、版本/哈希、许可证、缓存来源、运行接口与资源需求经预装检查报告并获得 Founder/决策 Chief 确认前，**不得运行候选 A、不得下载/安装/替换权重**（§7 禁止 14）。

**输入**：查询文本 `q` + 候选记忆文本 `m`（cross-encoder 以 `(q, m)` 拼接对输入，直接输出相关性分数；不依赖 mem0 原始 score）。

**计算步骤（方向性；具体接口以预装检查核验结果为准）**：
1. 用本地 fastembed `TextCrossEncoder`（或经核验的等价本地 cross-encoder 运行接口，**权重必须已预装缓存**）对 `(q, m)` 逐对前向推理；
2. 模型直接输出 `q` 与 `m` 的相关性 logit → sigmoid 归一化到 (0,1)（或按模型原生输出范围校准，校准集上确定映射参数）；
3. 决策阈值在校准集上确定，随机制冻结。

**输出分数**：0–1 连续相关性分数（cross-encoder 原生相关性，非余弦相似度）。

**针对第一轮根因的新增能力（R1）**：cross-encoder 将查询与记忆**拼接后联合编码**，能建模两者间的深层语义交互（"失眠"查询 vs 同一橘猫记忆在"天气"上下文下应判无关，在"失眠"上下文下应判相关）——这正是第一轮词法信号物理上无法做到的判别；判别力强于"手搓多维交互特征"（调研结论）。

**冗余降级规则（沿用）**：若实现中实际退化为单一向量余弦（如错误使用 embedding 而非 cross-encoder），或非冗余诊断 ρ ≥ 0.9，则自动降级为冗余基线，不作为正式候选；降级不影响候选 B 独立评估（§8 验收 2）。

**依赖约束（关键，约束 4/5）**：候选 A 所需 cross-encoder 权重**必须已预装缓存**（§5.4 P5 核验）；**若未缓存 → 只停止并标记候选 A 不可执行（§9.1 第 4 条），候选 B 独立继续；不得下载、安装或替换权重**；仅当没有任何正式候选可执行时才停止整轮 Spike（§9.2 第 10 条）。

### 3.2 候选机制 B：本地 embedding 校准集原型聚类 Gate（保留，调研方案 2/3 对照）

> 调研依据：ColBERT（late-interaction）与 RRF（多信号融合）经评估**不作为本候选的第二实现**——ColBERT 需新 checkpoint 与新索引（违反"仅已预装"约束）；RRF 是融合层而非词表覆盖替代，且本 Spike 单检索源下价值有限（详见 `spike-r2-research.md` 方案 2/3）。k-means 数据驱动主题空间保留为唯一方法。

**输入来源（全部列出）**：
- (a) 正式 8 Case 种子文本（`v2/migrations/002_eval.sql` E001–E008，已批准）；
- (b) 第一轮已入库校准检索样本文本（`spike/data/calibration/round-{1,2,3}/`，合成数据，已批准入库）；
- 以上为**唯一输入**；**不使用任何"通用知识"、未批准语料、人工词表、下载模型或新增依赖**；k-means 计划用纯 JS 实现或复用现有依赖实现——**"能否零新增依赖运行"属待核验事实**（§5.4 P4 核验现有依赖覆盖），不得表述为既成事实。

**计算步骤（单一方法：k-means 原型聚类）**：
1. 用本地 fastembed 将输入文本集合嵌入为向量集；
2. 对该向量集执行 **k-means 聚类**（k 为人工设定的元参数，仅在校准集上选定并随机制冻结；聚类本身纯数据驱动）得到 `k` 个主题原型向量 `P = {p_1…p_k}`；
3. 查询 `q` 与记忆 `m` 分别映射为与各原型的相似度分布 `a_q = [cos(v_q,p_1)…cos(v_q,p_k)]`、`a_m = [cos(v_m,p_1)…cos(v_m,p_k)]`；
4. 相关性 = 两分布加权相似（如加权余弦/JS 散度补数），映射到 (0,1)。

**输出分数**：0–1 连续相关性分数。

**针对第一轮根因的新增能力（R2）**：主题空间由**数据自动构建**（聚类），不依赖手工枚举词表；未见于词表的表达（如"下雨"）通过 embedding 自然落入原型分布，不因"词表未命中"而信号归零。

**人工输入边界**：人工仅设定元参数 `k`（聚类数）与相似度阈值；**不得人工枚举主题词表、不得人工标注原型语义**；空间构建只使用上述输入 (a)(b)，不使用 holdout 内容。

> 两个候选的详细机制（特征权重、k 选择、评估顺序）由 Builder 在实施计划中给出，**但不得超出上述两个候选方向与输入来源**；若证明需要第三机制、外部模型、未预装组件或新语料，停止并提交范围/依赖裁决。

## 5. 校准、非冗余诊断与冻结 Holdout（沿用第一轮纪律，DRAFT v1.2 §5 全量继承）

### 5.1 数据边界（不变）

- 只允许**合成评测数据** + 评测专用 user_id（`eval-spike-r2-<candidate>-<rand>` 格式）；**不得读取、复制或落盘真实用户内容**；
- 仅允许 loopback 本地服务；禁止一切非本机网络；
- 禁止运行时下载模型、权重或依赖；开始前按 §5.4 预装检查（P1–P6 沿用第一轮清单，含 fastembed 缓存核验）。

### 5.2 非冗余诊断（候选 A 专用；候选 B 信号源不同不依赖此诊断）

- 校准集计算候选 A 分数与 mem0 原始 score 的 Spearman ρ；ρ ≥ 0.9 → 降级冗余对照，**仅候选 A 降级，不影响候选 B 独立评估**；ρ < 0.9 仅证明非冗余，仍须通过全部质量/延迟/资源/泛化门；
- **冗余降级自检（Founder Review 1 第 1 条）**：除 ρ 外，候选 A 报告必须自查实现是否实际只使用了单一余弦（如仅 `dot` 一项）——若是，同样视为冗余基线，不作为正式候选。

### 5.3 校准集与冻结 Holdout（四步顺序不可颠倒）

1. **校准集**：E001–E005 场景真实本地检索样本，三轮重复采集（mem0 检索非确定性，禁止单轮结论）；
2. **标签规则**：正/负样本定义与人工复核沿用第一轮（关键词初判 + 人工复核，复核记录入库）；
3. **冻结 holdout（3–5 个场景，不参与调参）**：覆盖困难负例类型——多义词、他人属性、语义隐式关联、**未见过表达泛化（含第一轮失败类型"新天气表达"的新文本，禁止复用 H4 原文）**；S1 冻结（场景/标签/哈希），内容不得用于设计/调整任何候选机制；
4. **执行顺序**：① holdout 数据冻结 → ② 校准调参（仅校准集）→ ③ 机制冻结（版本 + 哈希）→ ④ holdout 一次性运行（运行后禁止继续调参）；
5. **可靠性判据（不变）**：校准集与冻结 holdout 各自 **F1 ≥ 0.9 且分离边际 > 0.1**；实测波动 > 0.1 → 判据自动失效 → 停止条件 1；
6. **样本量诚实声明**：如实声明样本量与置信局限；
7. **Reviewer 核对**：Builder 只提供冻结记录与提交历史，核对结论由独立 Reviewer 写入审查报告；
8. **holdout 隔离纪律（Founder Review 1 第 6 条 + 批准约束 7）**：
   - **候选设计不得读取 holdout 具体文本、标签或词汇**：候选机制设计（S2 之前）只接触校准集与已批准契约；
   - **"冻结早于候选设计"的精确语义（约束 7）**：S1 holdout 冻结**早于 Builder 的实现、参数和调优设计**（Builder 的代码、特征/权重/参数选择、调优过程均不得接触 holdout）；**不得声称早于已经批准的候选方向草案**——候选 A/B 方向已在本 DRAFT v1.2 批准（2026-08-12），该批准早于 holdout 冻结属正常且不构成冲突，不以此为"冻结先于设计"的证据；
   - **隔离方式**：① Git 隔离——S1 holdout 冻结提交必须**先于**任何 Builder 实现/调优提交（Reviewer 核对提交历史顺序）；② 数据路径分离——候选评分脚本只接收校准集数据路径参数，holdout 数据仅在 S7 一次性运行脚本中读取；③ 词表审计——候选 B 若产生任何聚类原型/词项输出，Spike 报告须对照 holdout 冻结内容证明无重叠（无 holdout 特有词进入机制）；
   - **可审计证据**：holdout 冻结时间戳/提交号/内容哈希（S1）+ Builder 实现/参数设计提交时间线 + 候选机制冻结时间戳/提交号/哈希（S3）+ 三者提交历史先后核验记录，全部入库供 Reviewer 核对。

### 5.4 预装检查（沿用第一轮，Spike 开始前强制门）

**共享依赖与候选专属依赖区分（PR #18 CHANGES_REQUESTED）**：预装检查按依赖类别分别判定，**不得笼统"任一缺失立即停止"**：

- **共享依赖（两候选共同依赖，缺失 → 影响两候选执行能力）**：P1 mem0-server loopback 可达、P2 版本、P3 PostgreSQL/评测表、P4 Node/pg 依赖、P6 网络边界环境审计——任一共享依赖缺失 → 提交范围/依赖裁决；**若缺失导致两个候选均不可执行 → 整轮停止（§9 停止条件 10）**；若仅影响部分能力（如 P4 pg 解析失败但候选 B 可纯内存运行），按实际可执行性判定；
- **候选 A 专属依赖（约束 4/5）**：P5 fastembed 缓存目录是否含 **cross-encoder 重排权重**（候选 A 所需，具体模型名/版本待核验）——**若未缓存 → 只停止并标记候选 A 不可执行**，提交范围/依赖裁决；候选 B 不依赖 reranker 权重（用 embedding 能力，P5 中 embedding 缓存为共享能力），独立继续；不得下载、安装或替换权重；
- **禁止执行会触发下载的实例化命令**（P1–P6 全部只读核验）。

**模型事实报告（约束 3/8；Review 2 实施计划必须包含，预装检查后产出 `spike-r2/model-facts.md`）**：对候选 A 涉及的具体模型/权重逐项报告：① 模型名称与版本；② 权重内容哈希；③ **许可证——按具体权重自身的模型卡（HuggingFace 模型卡等）记录，不得用代码仓库许可证代替模型许可证**；④ 缓存来源与路径（本地缓存目录、来源证明）；⑤ 运行接口（fastembed TextCrossEncoder 或等价接口，含版本）；⑥ 资源需求（内存/CPU/磁盘估算）。该报告须经 Founder/决策 Chief 确认后，候选 A 才可运行（约束 4）。

## 6. 延迟与资源门（沿用第一轮口径，DRAFT v1.2 §6 全量继承）

## 8. 验收标准（Spike 通过门；至少一个正式候选通过全部适用门 + 统一门即形成"存在可行候选"结论）

> **候选独立性（Founder Review 1 第 5 条）**：候选 A 与候选 B 各自核对**自己的适用门**（第 2 项），任一候选被降级/失败**不得阻止另一候选独立通过**；通过适用门后，两者统一接受第 3–11 项质量/延迟/资源/数据边界门。**"至少一个候选通过"的判断在候选级独立完成**——若候选 A 降级为冗余基线，候选 B 仍可单独通过并形成"存在可行候选"结论。

1. 预装检查通过（P1–P6，含 fastembed 缓存）；
2. **各候选适用门（互相独立）**：
   - 候选 A：通过非冗余诊断（ρ<0.9）**且**冗余降级自检通过（实现非单一余弦）；任一失败 → **仅候选 A 降级为冗余基线**，不参与后续门，**不影响候选 B**；
   - 候选 B：通过数据驱动定义核对（单一方法 k-means、输入来源仅 (a)(b)、无人工词表、无未批准语料/模型/依赖）；
3. 每个正式候选输出 0–1 连续可校准分数，完成 ≥3 轮真实本地检索测量；
4. 校准集 F1 ≥ 0.9 且分离边际 > 0.1（每候选分别评估）；
5. 冻结 holdout 一次性运行 F1 ≥ 0.9 且分离边际 > 0.1（四步顺序执行；运行后无继续调参）；
6. 延迟门：增量 P95 ≤ 200ms、总预算 P95 ≤ 1000ms；
7. 资源门：内存 ≤ 512MB、CPU ≤ 500ms；
8. 网络与数据边界：仅 loopback、零非本机调用、仅合成数据、种子清理核验；
9. 零产品改动：分支 diff 仅含 TASK-006 文档与 `spike-r2/` 文件；
10. 证据完整落盘：脚本、原始数据、标签复核、冻结记录（时间戳/提交号/哈希）、审计、失败尝试、holdout 隔离审计证据（S1 先于 S3 的提交历史核验）；
11. 报告诚实：样本量声明、波动范围、失败记录（含失败候选）、ρ、增量口径、与 DRAFT v1.2 判据对标、**"Spike 通过 ≠ TASK-006 完成"声明**。

**回归证明**：E001/E003 正向场景在冻结机制下逐轮指标（候选不砍正向召回）；强约束（E006/E007/E008）不涉及（零产品改动）。

## 9. 停止条件（PR #18 CHANGES_REQUESTED 修订：候选级与整轮级规则分开）

> **候选级停止**：某候选触发候选级条件 → **只停止并标记该候选**，另一候选独立继续；不停止整轮。
> **整轮立即停止红线**：任一红线触发 → **立即停止整轮 Spike**，提交 Change Request / 返回 Founder，不得继续。

### 9.1 候选级停止（只停止对应候选，另一候选可继续）

1. **候选质量不达标**：该候选校准集或冻结 holdout 分离边际 ≤ 0.1（或实测波动 > 0.1 使判据失效）→ 只停止该候选并如实记录失败；
2. **正向召回退化**：该候选修复 E004 必然导致 E001 等正向召回明显退化 → 只停止该候选；
3. **必须削弱测试/改判定规则/手工枚举词表/固定字面量硬编码才能变绿** → 只停止该候选；
4. **候选专属依赖缺失**：候选 A 专属（cross-encoder 权重未缓存或运行接口不可用）或候选 B 专属（校准数据源缺失等）→ **只停止并标记该候选不可执行**，提交范围/依赖裁决，另一候选独立继续（§5.4 区分共享/专属依赖）。

### 9.2 整轮立即停止红线（任一触发 → 整轮停止）

5. **数据外发 / 非本机网络访问**（Spike 机制实际发起外部调用）；
6. **接触或落盘真实用户数据**（非合成数据）；
7. **冻结失效**：无法建立与校准数据独立的冻结 holdout 证据（holdout 不可建立、不独立，或冻结纪律被破坏）；
8. **时间盒到期**（5 工作日 / 3 轮迭代，先到者）未收敛；
9. **需要超出批准范围的改动**（含必须外发才能解决）；
10. **没有任何正式候选可执行**（共享依赖缺失导致两个候选均不可执行，或候选级停止后无剩余可执行候选）→ 整轮停止，提交 Change Request 由 Founder 裁决候选范围。

> 说明：候选级停止（§9.1）不阻止另一候选继续；整轮停止（§9.2）才终止 Spike。两候选均因候选级条件停止（§9.1 第 1/2/3/4 条各自触发）时，即落入 §9.2 第 10 条"无剩余可执行候选"，整轮停止。
