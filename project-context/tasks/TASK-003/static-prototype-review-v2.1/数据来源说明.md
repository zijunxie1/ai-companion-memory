> 交付物配套文档。本页面是**单次版本评测结果页**，全部数据来自静态评测快照，
> 页面不暗示任何实时/自动能力。

## 1. 三类数据来源（页面上逐模块标注）

| 来源类型 | 含义 | 覆盖内容 |
|---|---|---|
| **固定评测快照** | 来自 `E:\正式作品\v2\app\src\lib\eval-data.ts` 的静态评测结果，由人工评测产生 | 8 个 Case 的分数/回复/召回/写入、强约束结果、GSB 结论、4 条本次发现、7 条 Bad Case |

| **V2 Trace 待新增** | 当前后端尚未采集 | Gate 命中、被过滤 Memory 明细、实际 Prompt 注入——标注「未采集（待 V2 Trace 增强）」 |

## 3. 后端能力边界（当前真实状态）

| 数据 | 当前可真实提供？ | 页面处理 |
|---|---:|---|
| 用户输入 / AI 回复 | ✅ Trace 已存储 | 静态快照内直接展示 |
| 召回 Memory / 分数 | ✅ Chat route 已记录 | 静态快照内展示 |
| 召回原因 | ✅ 已生成并存储 | 静态快照无此字段 → **未采集** |
| Memory 写入 | ⚠️ 异步（初始空，后台更新） | 静态快照展示评测时的写入结果 |
| Prompt 版本 / 延迟 | ✅ Trace 已存储 | 静态快照无此字段 → **未采集** |
| Gate 命中 / 被过滤 Memory / 实际 Prompt 注入 | ❌ 未采集 | **未采集**（标注「待 V2 Trace 增强」） |
| Priority 排序 | ❌ 无排序规则服务 | 不展示「优先级」；只按严重程度展示「本次评测发现」 |
| 根因与修复方向 | ❌ 静态人工结论 | 标注「原因假设 / 人工分析」，不包装为自动诊断 |

## 4. 页面模块与来源标注位置

- 运行信息栏：`数据来源：固定评测快照`
- 本次评测发现：右上 `数据来源：固定评测快照`，每条含「证据 Case + 原因假设」
- 强约束与 GSB：`来源：人工判断 · 固定评测快照`
- 评测指标：`来源：人工判断（评分）`
- Case 结果：行展开面板与详情 Drawer 内标注 `固定评测快照`
- Trace 证据：逐行标注来源，缺失项为 `未采集` 徽标
- Bad Case 管理：`数据来源：固定评测快照`；更新时间/负责人无数据 → 显示 `—（未提供）`
