## 新发现的问题

| # | 问题 | 根因 | 严重程度 |
|---|---|---|---|
| N1 | 异步写入延迟导致前两轮无 Memory 可召回 | mem0.add() 异步执行，第一条消息的 Memory 在第三条消息时才完成写入 | 中 |
| N2 | E004 代码执行节点输出原始 JSON（reply/action/inner/emotion 裸露） | Dify 代码执行节点未正确解析 LLM 的 JSON 输出 | 中 |
| N3 | E004 AI 说"没告诉我名字"——Memory 召回了小橘但 LLM 没使用 | LLM 过度保守，Dify Prompt 需要调整 | 中 |
| N4 | 召回阈值 0.35 仍然偏低——天气能召回失眠和吉他 | 阈值需要调高到 0.40-0.45 | 低 |

## 面试叙事

> 我跑了第一轮 Baseline，发现 False Memory Rate 高达 40%——包括身份证号写入和 LLM 幻觉。我定位了根因（抽取 Prompt 缺隐私规则 + 无召回阈值），修复后重跑 Baseline，False Memory Rate 降到 0%。
>
> 但也发现了新问题——异步写入的延迟导致前两轮对话没有 Memory 可用。这是性能优化（异步）和功能完整性（即时可用）之间的 trade-off，我在后续版本中会优化。
>
> 这个过程展示了我从评测发现问题→定位根因→修复→验证的完整闭环。
