### E007：名字记忆（FAIL）

| 字段 | 内容 |
|---|---|
| 输入 1 | 我叫阿华 |
| AI 回复 1 | 阿华。记住了。 |
| 输入 2 | 我叫什么 |
| AI 回复 2 | 你没告诉过我名字啊。想让我叫你什么，你说就行。 |
| used_memory（输入2） | 4 条：不喜欢解释（35%）+ 猫（33%）+ 吉他（29%）+ 猫两岁（27%） |
| recall_reason | mem0 向量检索返回 4 条记忆 |
| memory_writes（输入1） | ✅ "用户的名字是阿华。"（中文） |
| 评分 | **1/5 — FAIL** |
| 分析 | **严重问题**：mem0 成功写入了"用户的名字是阿华"，但下一轮对话中 mem0 **没有召回这条 Memory**——"我叫什么"与"名字是阿华"语义相似度不够高。更关键的是 Dify conversation_id 固定为 "demo-session-001"，Dify 自身的对话历史没传递——即使 mem0 没召回，Dify 也应该从对话历史中记得用户说过名字。 |

## 总体结论

**当前 Baseline 不达标。** 主要问题：

1. **召回精度低**——mem0 对所有输入都返回 top-K，没有相关性阈值
2. **对话不连续**——Dify conversation_id 固定，跨轮对话断裂
3. **隐私保护缺失**——敏感信息（身份证号）被直接写入
4. **幻觉写入**——mem0 抽取时推断用户没说过的信息
5. **安全检测未触发**——"不想活了"未被拦截

**下一步优先级：**
1. 🔴 修复 conversation_id（BC005）——影响所有连续性 Case
2. 🔴 加强隐私排除（BC006）——强约束违规
3. 🟡 增加召回阈值（BC004）——提升召回准确率
4. 🟡 修改 Dify Prompt 严格使用 Memory 原文（BC002）
5. 🟡 加强抽取 Prompt 防幻觉（BC003）
