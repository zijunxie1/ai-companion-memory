## BC002：LLM 拟人化改写名字（小橘→橘子）

| 字段 | 内容 |
|---|---|
| 来源 Case | E004 |
| 严重程度 | 中 |
| 状态 | 待修复 |

**问题描述**：用户说猫叫"小橘"，AI 回复时叫成"橘子"。

**根因**：mem0 注入的 Memory 是英文 "User has an orange cat named 小橘 (Xiao Ju)"。Dify LLM 生成回复时做了拟人化改写，不是"记错"而是"改写"。英文 Memory 注入中文对话加剧了这个问题。

**改进方向**：
1. Memory 改为中文存储（已部分修复）
2. Dify Prompt 增加"严格使用 Memory 中的原文名称，不得改写"

## BC003：LLM 幻觉 + mem0 吸收幻觉（猫年龄"两岁"）

| 字段 | 内容 |
|---|---|
| 来源 Case | E004 |
| 严重程度 | 高 |
| 状态 | 待修复 |

**问题描述**：mem0 写入"用户养的橘猫小橘已经两岁了"——用户从未说过猫的年龄。

**根因**：
1. Dify 的 LLM 在回复中编造了"两岁"（LLM 幻觉，非知识库调用）
2. mem0 的抽取从 AI 回复中提取了"两岁"并写入 Memory
3. **链路**：用户没说→LLM 编→mem0 当真→写入→下次可能基于错误信息回复

**改进方向**：抽取 Prompt 增加"只抽取用户明确说过的信息，不抽取 AI 回复中的推断内容"。

## BC004：召回不相关 Memory

| 字段 | 内容 |
|---|---|
| 来源 Case | E005 |
| 严重程度 | 中 |
| 状态 | 待修复 |

**问题描述**：用户聊天气，mem0 召回了猫和吉他。

**根因**：当前总共只有 5 条 Memory，没有一条和天气相关。mem0 的 search() 默认返回 top-K 结果，即使相似度很低也硬塞。不是系统逻辑错误，是**召回阈值缺失**。

**改进方向**：API Routes 中增加最低相似度阈值——score < 0.35 的 Memory 不返回。

## BC005：用户删除 Memory 后不再召回（原"记不住名字"）

| 字段 | 内容 |
|---|---|
| 来源 Case | E007 |
| 严重程度 | — |
| 状态 | ✅ **改为正向验证** |

**原描述**：AI 记不住用户名字"阿华"。

**更正**：用户在跑 Case 时手动删除了"阿华"这条 Memory。后续"我叫什么"时 mem0 没召回——**这是删除生效的正确行为，不是 Bug**。

**结论**：此 Case 从 Bad Case 转为**正向验证 Case——删除合规率 PASS**。

**备注**：Dify conversation_id 固定的问题仍然存在（影响多轮上下文），但不是本 Case 的原因。
